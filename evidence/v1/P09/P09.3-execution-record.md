## 1. Components Implemented
- `Coleza\Domain\Servers\Entities\Location`: Datacenter location entity tracking name, slug, ISO country code, city, datacenter facility, and active status.
- `Coleza\Domain\Servers\Entities\ServerPool`: Server grouping entity managing provider slug association, datacenter location, pool allocation strategies (`least_loaded`, `round_robin`, `fill_first`, `random`), metadata, and active status.
- `Coleza\Domain\Servers\Entities\ServerCapacity`: Server quota and load metrics entity managing account limits, disk limits, bandwidth limits, memory limits, percentage usage calculations, headroom checks (`hasAccountHeadroom`, `hasDiskHeadroom`, `hasBandwidthHeadroom`), composite load score calculation (`calculateLoadScore`), and immutable increment/decrement operations.
- `Coleza\Domain\Servers\Entities\Server`: Infrastructure server model capturing hostname, IP address, provider association, pool and location mapping, status states (`active`, `maintenance`, `disabled`, `full`), capacity metrics, connection port, authentication secrets (strictly masked via `getMaskedSecret()`), and provider DTO conversion (`toServerConnectionDto()`).
- `Coleza\Domain\Servers\Services\ServerService`:
  - Table schemas for `locations`, `server_pools`, and `servers`.
  - Full CRUD operations for locations, server pools, and servers with uniqueness validations (`slug`, `hostname`).
  - Automated capacity allocation tracking: `incrementAccountCount`, `decrementAccountCount` with automatic status transitions to `full` when saturated and restoration to `active` when headroom becomes available.
  - Usage synchronization and capacity evaluation (`updateServerUsage`, `checkCapacity`, `setServerStatus`).
