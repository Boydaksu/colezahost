## 1. Components Implemented
- `Coleza\Domain\Servers\Capacity\Exceptions\ReservationException`: Base exception capturing structured error codes and contexts for capacity reservation operations.
- `Coleza\Domain\Servers\Capacity\Exceptions\CapacityExceededException`: Specific exception thrown when requested allocation exceeds available server quota limits.
- `Coleza\Domain\Servers\Capacity\Entities\CapacityReservation`: Lifecycle reservation entity managing unique tokens, server associations, pool/service/order mapping, reserved quotas (accounts, disk, bandwidth), statuses (`reserved`, `committed`, `released`, `expired`), timestamps, release reasons, and TTL expiry calculations.
- `Coleza\Domain\Servers\Capacity\Services\CapacityReservationService`:
  - `capacity_reservations` table management.
  - Two-phase allocation lifecycle:
    - `reserve(...)`: Atomically checks capacity and holds server headroom with TTL protection.
    - `commit(...)`: Transitions reservations to permanent status upon successful checkout/provisioning.
    - `release(...)`: Immediately refunds allocated server quota if an order is cancelled or provisioning fails.
    - `expireStaleReservations(...)`: Automated garbage collector releasing expired reservations and restoring server capacity.
    - Query helpers: `findReservationByToken`, `findActiveReservationForService`, `listReservationsForServer`.
