## 1. Components Implemented
- `Coleza\Domain\Providers\Settings\ProviderSettingDefinition`: Setting field specification managing data types (`string`, `int`, `bool`, `secret`, `url`, `select`), validation logic, secret flags (`isSecret`), labels, defaults, and option constraints.
- `Coleza\Domain\Providers\Settings\ProviderSettingSchema`: Provider module schema repository organizing field definitions, providing standard configurations for hosting platforms (`cPanel`, `DirectAdmin`), and separating public defaults from secret configurations.
- `Coleza\Domain\Providers\Settings\ResolvedProviderConfig`: Runtime configuration object aggregating schema defaults, persistent database settings, and decrypted Vault secrets with typed accessors (`getString`, `getInt`, `getBool`, `getSecret`) and security-conscious masking in `toSafeArray()`.
- `Coleza\Domain\Providers\Settings\ProviderSettingService`:
  - `provider_module_settings` table management.
  - Safe credential management: Sensitive parameters (e.g. WHM tokens, API keys, passwords) are automatically mapped to and encrypted inside `VaultService` (`provider:{provider_slug}` namespace). Non-sensitive settings are persisted in database records.
  - Strict secret masking: `getPublicSettings(...)` strictly returns masked representations (`••••••••`) for administrative UI and API exposure.
  - Vault secret rotation: Prevents masked UI placeholders from overwriting active Vault credentials while permitting active rotations with new plaintext values.
  - Runtime configuration resolution: `resolveEffectiveConfig(...)` decrypts Vault credentials seamlessly for authorized background workers and provisioning adapters.
  - Cleanup: `deleteSettings(...)` purges database records and destroys associated Vault secrets.
