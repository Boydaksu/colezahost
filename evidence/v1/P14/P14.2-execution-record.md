## 1. Subphase Scope & Objective
Establish advanced fraud defense primitives covering entity listing, rate anomaly detection, and account linkage:
- **Allow / Watch / Deny Lists Engine:**
  - `FraudListType`: `ALLOW`, `WATCH`, `DENY` outcomes.
  - `FraudListEntryType`: `IP`, `EMAIL`, `COUNTRY`, `USER_ID`, `FINGERPRINT`, `CARD_BIN`.
  - Flexible matching:
    - IP: Exact and IPv4 CIDR subnet matching (e.g. `10.200.0.0/16`).
    - Email: Exact and wildcard domain matching (e.g. `*@domain.com`, `@domain.com`, `domain.com`).
    - Country: ISO code comparison.
  - State and expiration lifecycle: `isExpired`, deactivation, active lookup filtering.
  - Storage table `fraud_list_entries`.
- **Velocity Tracker & Burst Analysis:**
  - `VelocityEvent` and `VelocityTrackerService` tracking rate bursts across sliding time windows:
    - Hourly IP order attempts.
    - 10-minute user order frequency.
    - 15-minute payment failure spikes.
  - Storage table `fraud_velocity_events`.
- **Related-Account Linkage & Sybil Detection:**
  - `AccountLinkageService` and `RelatedAccountResult` mapping identity networks:
    - Correlates user accounts sharing IP and network signatures.
    - Detects links to confirmed fraudulent accounts (prior `REJECT` decisions or active `DENY` list entries).
    - Clusters multi-account syndicates.
- **Risk Rule Implementations:**
  - `ListMatchingRule`: Triggers `RULE_DENYLIST_MATCH` (score: 100, critical) or `RULE_WATCHLIST_MATCH` (score: 40, high).
  - `VelocityRiskRule`: Triggers `RULE_VELOCITY_EXCEEDED` for rapid-fire orders or excessive payment failures.
  - `RelatedAccountsRiskRule`: Triggers `RULE_RELATED_ACCOUNTS` for multi-accounting clusters and linked fraud history.
