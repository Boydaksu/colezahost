## 1. Subphase Scope & Objective
Establish statutory data subject privacy requests (GDPR, CCPA, KVKK) with step-up verification and sensitive data export compilation:
- **Privacy Request Lifecycle (`PrivacyRequestType`, `PrivacyRequestStatus`):**
  - Statutory request types: `EXPORT` (Right of access & portability), `ERASURE` (Right to be forgotten), `RESTRICTION` (Restriction of processing), `RECTIFICATION`.
  - Workflow states: `PENDING_VERIFICATION`, `VERIFIED`, `PROCESSING`, `COMPLETED`, `REJECTED`, `CANCELLED`.
  - Storage table `privacy_requests`.
- **Step-Up Authentication & Security Enforcement:**
  - Mandatory step-up challenge before fulfillment: no data export or erasure is permitted while unverified.
  - Multi-factor 6-digit OTP code + secure 64-character token.
  - Plaintext code is never stored in database; only SHA-256 hash is persisted.
  - Rate limiting & brute-force defense: maximum 3 failed attempts before permanent request lockout and rejection.
  - Time-to-live expiration enforcement.
- **Data Export Package & Automated Sanitization:**
  - `PrivacyExportPackage` assembling multi-domain records: user profile, consents history, organization memberships, orders, invoices, services, domains, and support tickets.
  - Strict PII / confidential data sanitization: passwords, password hashes, 2FA secrets, API keys, and session tokens are cleanly scrubbed prior to packaging.
  - Cryptographic SHA-256 payload checksum (`package->verifyIntegrity()`) ensuring tamper detection.
