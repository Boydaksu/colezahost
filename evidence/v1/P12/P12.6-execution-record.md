## 1. Subphase Scope & Objective
Establish bulletproof operation idempotency, uncertain timeout mitigation, and asynchronous state reconciliation for all mutating domain registrar actions:
- **Operation Entity & Storage (`DomainOperation`, `DomainOperationRepository`):**
  - Storage table `domain_registrar_operations` with a strict `UNIQUE (idempotency_key)` constraint.
  - Lifecycle statuses: `pending`, `processing`, `succeeded`, `failed`, `uncertain`.
  - Captures remote transaction IDs, error codes/messages, payloads, and results.
- **Idempotent Operation Execution (`IdempotentDomainOperationService`):**
  - Caches successful operation outcomes; duplicate executions with the same idempotency key immediately return the cached success result without re-calling the registrar API.
  - Concurrent execution guard: blocks duplicate invocations while an operation is in `processing` status.
  - Timeout & Network Interruption Detection: captures cURL timeouts, connection drops, gateway timeouts, and transport exceptions.
  - Transitions ambiguous outcomes into `STATUS_UNCERTAIN` instead of treating them as failures or leaving dangling orders.
- **Automated Reconciliation Engine (`DomainOperationReconciliationService`):**
  - Inspects uncertain operations and reconciles against registrar reality:
    - **Registration Reconciliation:** Queries registrar nameservers and availability. If remote domain records exist, reconciles to `succeeded` and activates local domain. If domain remains available, reconciles to `failed` allowing safe retry or cancellation.
    - **Renewal Reconciliation:** Queries remote domain status and expiration. If extended, reconciles to `succeeded` and extends local domain due date.
  - Provides both targeted single-operation reconciliation and batch reconciliation (`reconcileAllUncertain`).
  - Records chronological timeline events for all reconciliation milestones (`reconciled_register_success`, `reconciled_register_failed`, `reconciled_renew_success`).
