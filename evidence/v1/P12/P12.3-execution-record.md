## 1. Subphase Scope & Objective
Establish standardized registrar provider capability interfaces, command DTOs, result objects, provider registry, and secure credential storage using Coleza Vault:
- **Registrar Capability Matrix:**
  - `RegistrarCapability` enumerating provider capabilities: `availability_check`, `register`, `renew`, `transfer`, `update_nameservers`, `set_lock`, `get_epp_code`, `update_contacts`, `dns_management`, `email_forwarding`, `id_protection`.
- **Command & Result DTOs:**
  - `DomainAvailabilityResult`: encapsulation of availability status, premium flag, prices, currency, and unavailability reason.
  - `DomainRegistrationCommand`: strong DTO for domain, years, nameservers, contact profiles, WHOIS privacy flag, and optional DNS attributes.
  - `DomainRenewalCommand`: strong DTO for domain renewal years, current expiration, and idempotency key.
  - `DomainTransferCommand`: strong DTO for transfer domain, EPP auth code, years, nameservers, and contacts.
  - `RegistrarOperationResult`: standardized result capturing success/failure, operation name, domain, remote transaction ID, expiration date, error code, error message, raw response, and execution timestamp.
- **Registrar Provider Interface & Registry:**
  - `RegistrarProviderInterface`: strict contract standardizing lifecycle operations across all domain registrars.
  - `RegistrarRegistry`: dynamic provider registry with default fallback selection and capability checking.
- **Vault Registrar Settings Manager:**
  - `RegistrarConfiguration`: registrar credentials and settings entity with automatic secret masking in `__debugInfo()` and `toArray(maskSecrets: true)` using `••••••••`.
  - `VaultRegistrarSettingsManager`: stores sensitive registrar API keys and secrets encrypted in the Vault under namespace `registrar:{registrarId}`, with non-sensitive configurations saved in `registrar_configurations`.
  - Provides full auditing of credential storage, retrieval, and deletion actions.
