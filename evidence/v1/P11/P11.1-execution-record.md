## 1. Subphase Scope & Objective
Implement the foundational Coleza Automation Engine adhering strictly to the architecture constitutions:
- **Triggers:** Generic trigger interface, event triggers with pattern/wildcard and payload matching, schedule/cron triggers, and manual dispatch triggers.
- **Trigger Context:** Dot-notation resolution across arbitrary nested data structures with mutation and cloning capabilities.
- **Conditions & Evaluators:** Rich operator set (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`, `not_contains`, `starts_with`, `ends_with`, `in`, `not_in`, `is_null`, `is_not_null`, `regex`, `between`), type-safe numeric/string evaluation.
- **Logical Grouping:** AND / OR composition groups with short-circuit evaluation and arbitrary nested condition trees.
- **IF-ELSE Branching:** Structured branching evaluating conditions to route execution deterministically to `THEN`, `ELSE`, or `NONE` action branches.
- **Action Abstraction & Handlers:** Decoupled action definitions, registry, parameter interpolation templates (`{{ ... }}`), and standard built-in handlers (`log`, `context.set`, `callback`).
- **Automation Engine:** Prioritized rule execution, batch event processing, detailed diagnostics, and execution reporting without cross-domain leakage.

## 4. Architectural Rules Audit
- **Strict typing:** `declare(strict_types=1);` present in all files.
- **Domain boundaries:** Automation engine is self-contained in `Coleza\Domain\Automation` with abstract `ActionHandlerInterface` allowing external domains to attach actions cleanly via adapters.
- **Cross-domain purity:** No direct database or foreign entity mutations.
- **Sensible defaults & error resilience:** Action execution failures are captured in `ActionResult` with stack traces/diagnostics without aborting surrounding engine workflows.
