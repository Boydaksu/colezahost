## 1. Subphase Scope & Objective
Implement dedicated Domain Command Adapters connecting the Coleza Automation Engine to external bounded contexts strictly respecting architectural boundaries:
- **No Direct Database Bypass:** Under `02-architecture/DOMAIN_BOUNDARIES.md`, automation never mutates database tables, executes raw SQL queries, or interacts directly with repositories of other domains.
- **Service Command Adapters:** Adapts `service.suspend`, `service.unsuspend`, `service.terminate`, `service.cancel`, and `service.renew` actions strictly through the official `ServiceService` application commands.
- **Billing Command Adapters:** Adapts `invoice.generate_renewal` and `invoice.update_status` actions through `RenewalInvoiceService` and `InvoiceService`.
- **Notification Command Adapters:** Adapts `notification.send` and `notification.in_app` actions through `NotificationEngine` and `NotificationCenterService`.
- **Unified Adapter Registry:** Convenience coordinator `AutomationDomainAdapterRegistry` registering domain command handlers cleanly into the engine's `ActionRegistryInterface`.

## 4. Architectural Rules Audit
- **Strict typing:** `declare(strict_types=1);` present in all adapter classes.
- **Zero repository/DB bypass:** No PDO or SQL statement in `src/Domain/Automation/Adapters/`. Every mutation routes through domain services (`ServiceService`, `InvoiceService`, `RenewalInvoiceService`, `NotificationEngine`, `NotificationCenterService`).
- **Resilience:** Domain exceptions and validation failures are gracefully caught and returned as structured failure `ActionResult`s with diagnostic messages without crashing engine workflows.
