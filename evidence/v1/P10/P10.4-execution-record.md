## 1. Components Implemented
- `Coleza\Domain\Provisioning\Workflows\HostingProvisioningStep`:
  - Canonical 6-step enum representing `VALIDATE`, `PLACE`, `RESERVE`, `REMOTE`, `VERIFY`, and `ACTIVATE`.
- `Coleza\Domain\Provisioning\Workflows\HostingProvisioningRequest`:
  - Typed request DTO carrying service identification, optional domain/username/password overrides, target hosting package identifier, quota limits (`requiredDiskMb`, `requiredBandwidthMb`), dedicated IP requirement, and placement hints (pool, location, preferred server).
- `Coleza\Domain\Provisioning\Workflows\HostingProvisioningResult`:
  - Structured result entity tracking execution outcome, active step, completed step trail, server ID, reservation token, remote IP, assigned nameservers, error classification, and operation UUID.
- `Coleza\Domain\Provisioning\Workflows\HostingProvisioningWorkflow`:
  - Orchestrates the full end-to-end 6-phase hosting provisioning sequence:
    1. **VALIDATE:** Verifies service exists and is in `pending` state (idempotently succeeds if already `active`); strictly validates cPanel username formatting (length 1–16, starts with letter, lowercase alphanumeric, denies reserved usernames like `root`, `cpanel`, `whm`); validates domain format; generates secure passwords when omitted; resolves target plan package.
    2. **PLACE:** Evaluates target node using `PlacementEngine` across server pools or locations using active placement strategies (least loaded, fill first, round robin); assigns a pending placement record in `ServicePlacement`.
    3. **RESERVE:** Atomically claims node capacity via `CapacityReservationService`, incrementing allocated accounts and quotas; on headroom failure, evicts placement and halts.
    4. **REMOTE:** Dispatches `CreateAccountOperation` to `CpanelProvider` over secure WHM API with connection credentials, account quotas, and contact metadata; upon remote failure, automatically triggers two-phase compensation (releases capacity reservation and evicts service placement).
    5. **VERIFY:** Performs post-creation probe via remote WHM `accountsummary` to confirm account presence, active status, and network IP allocation; rolls back reservation on probe failure.
    6. **ACTIVATE:** Permanently commits capacity reservation (`commit`), promotes service placement status to `placed`, updates service entity to `active` with bound credentials and host details, and writes completed audit log to `ProvisioningOperationService`.
- `Coleza\Domain\Servers\Capacity\Entities\CapacityReservation`:
  - Added `getReservationToken()` alias method for consistent token retrieval across services.
