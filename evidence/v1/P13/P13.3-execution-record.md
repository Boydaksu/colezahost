## 1. Subphase Scope & Objective
Deliver hardened attachment handling, file security verification, tamper detection, private/internal attachment segregation, and access control:
- **Attachment Entity & Storage:**
  - `TicketAttachment` model: `id`, `ticket_id`, `message_id`, `user_id`, `original_filename`, `storage_key`, `file_size_bytes`, `mime_type`, `sha256_hash`, `is_private`, `metadata`, and timestamps.
  - Storage table `support_ticket_attachments` with unique storage key constraint.
- **Attachment Security Policy:**
  - `AttachmentSecurityPolicy` enforcing multi-layered upload protection:
    - **Extension Whitelist:** Images (`png`, `jpg`, `jpeg`, `gif`, `webp`), documents (`pdf`, `txt`, `log`, `csv`), archives (`zip`, `tar`, `gz`).
    - **Forbidden Executable Rejection:** Immediate rejection of `php`, `phtml`, `phar`, `exe`, `dll`, `sh`, `bat`, `cmd`, `svg`, `js`, `html`, `.htaccess`, etc.
    - **Double-Extension Protection:** Disallows spoofed names (e.g. `invoice.php.png` or `contract.exe.pdf`).
    - **Null Byte & Traversal Protection:** Rejects filenames with `\0`, `%00`, `../`, or `..\`.
    - **Content Sniffing:** Inspects text payloads for embedded script tags (`<?php`, `<?=`, `<script`).
    - **Size Bounds:** Enforces minimum (> 0 bytes) and maximum payload limits (configurable, 10MB default).
    - **Safe Sanitization:** Normalizes uploaded filenames preventing shell injection and special characters.
- **Storage Driver & Filesystem Isolation:**
  - `AttachmentStorageInterface` contract.
  - `InMemoryAttachmentStorage` for testing and memory-backed ephemeral storage.
  - `PrivateAttachmentStorage` persisting files outside web root (`storage/private/attachments/`) with `0700` permissions and strict traversal protection.
- **Tamper Detection & Cryptographic Integrity:**
  - Computes and stores SHA-256 hash upon attachment upload.
  - `readContent` verifies payload against recorded SHA-256 checksum; throws `RuntimeException` if altered or corrupted.
- **Private Attachment Segregation & Access Controls:**
  - Private attachments (`is_private = 1`) associated with internal notes or marked private are invisible to customers (`getTicketAttachments(includePrivate: false)`).
  - Staff members have access to all public and private attachments.
  - Cross-customer access prevention (`canAccess` validates user ownership against ticket owner and uploader).
  - Deletion authorization ensures only uploader or staff can delete attachments.
