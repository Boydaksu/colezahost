## 1. Subphase Scope & Objective
Establish core support desk organizational structure, department administration, agent assignment mappings, ITIL-compliant ticket status state machines, and priority escalation baselines:
- **Support Departments:**
  - `Department` entity encapsulating department identity: `id`, `name`, `description`, `email`, `is_public` (customer visibility), `is_active`, `sort_order`, `metadata`, and timestamps.
  - Storage table `support_departments` with unique name constraint.
- **Department Agents & Membership:**
  - `DepartmentAgent` entity modeling agent-department mappings: `department_id`, `user_id`, `role` (e.g. agent, lead, supervisor), `can_assign` eligibility, `receives_notifications`, `is_active`, and metadata.
  - Storage table `support_department_agents` with composite unique constraint `(department_id, user_id)`.
  - Capable of querying assignable agents for round-robin dispatch, agent departments across multiple assignments, and safe department deletion protection.
- **Ticket Status State Machine:**
  - `TicketStatus` value definition covering full ITIL service desk lifecycle: `open`, `customer_reply`, `in_progress`, `answered`, `on_hold`, `resolved`, `closed`.
  - Strict transition validation matrix preventing illegal status jumps while supporting standard workflow transitions and ticket re-opening policies.
  - Lifecycle state classification helpers (`isOpen`, `isWaitingStaff`, `isWaitingCustomer`, `isPaused`, `isResolved`, `isClosed`, `isTerminal`).
  - Localization labels (EN, TR) and UI status badge classes.
- **Ticket Priority & SLA Baselines:**
  - `TicketPriority` value definition: `low`, `medium`, `high`, `critical`.
  - Numeric weight escalation comparison (`isHigherThan`).
  - Default SLA first-response and resolution target minutes (foundation for P13.5 SLA scheduler).
  - Localization labels (EN, TR) and UI badge styles.
