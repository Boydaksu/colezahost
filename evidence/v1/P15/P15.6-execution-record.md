## 1. Subphase Scope & Objective
Establish robust currency conversion, timezone alignment, and data freshness semantics for the analytics baseline:
- **Historical Currency Rates (`CurrencyAnalyticsContext`, `ConvertedAmountResult`):**
  - Guarantee that historical analytics and read models are converted using exchange rates registered for the exact date of transaction/snapshot.
  - Guard against silent historical recalculation using today's live rates (protecting accounting reproducibility and constitution mandates).
  - Explicit error handling when missing historical rate data.
- **Timezone Boundary Alignment (`TimezoneAnalyticsContext`):**
  - Translate tenant or reporting timezone day boundaries (`YYYY-MM-DD 00:00:00` to `23:59:59`) into precise UTC datetime ranges (`start`, `end`) for underlying SQL querying.
  - Seamless handling across various timezones (e.g. UTC, Europe/Istanbul, America/New_York) factoring in offsets and daylight transitions.
- **Data Freshness and Consistency Evaluation (`AnalyticsFreshnessService`, `DataFreshnessStatus`, `DataFreshnessMetadata`):**
  - Compute elapsed lag between latest analytical read model aggregation timestamp (`rebuilt_at`) and current system clock.
  - Categorize freshness into `REALTIME` (< 120s), `NEAR_REALTIME` (< stale threshold), and `STALE` (>= stale threshold).
  - Compare latest transaction activity timestamp against latest rebuild time to flag consistency state (`isConsistent() = false` if transactions occurred post-rebuild).
