## 1. Subphase Scope & Objective
Establish robust role-based access control (RBAC), multi-tenant data scope isolation, and sensitive metric redaction for the Analytics domain:
- **Analytics User Context (`AnalyticsUserContext`):**
  - Security principal model conveying user ID, staff status, superadmin flag, tenant organization membership/role, and granted permission slugs.
  - Dedicated factory initializers (`forSuperAdmin`, `forStaff`, `forOrgUser`).
- **Analytics Permission Enforcement (`AnalyticsPermissionService`):**
  - Granular RBAC gates for all dashboard types:
    - `DashboardType::OWNER` requires `analytics.view_executive` or `analytics.view_owner`.
    - `DashboardType::FINANCE` requires `analytics.view_financial`.
    - `DashboardType::SALES` requires `analytics.view_sales`.
    - `DashboardType::OPERATIONS` requires `analytics.view_operations`.
    - `DashboardType::SUPPORT` requires `analytics.view_support`.
  - Sensitive action guards:
    - Historical read model rebuilding requires `analytics.rebuild`.
    - Analytical dataset exporting requires `analytics.export`.
  - Metric-level access control based on metric taxonomy categories (e.g. INVOICE, CASH, REVENUE, SUBSCRIPTION, OPERATIONS, SUPPORT).
  - Explicit enforcement guards throwing `AuthorizationException` (HTTP 403 `PERMISSION_DENIED`) on forbidden operations.
- **Multi-Tenant Data Scope & Redaction (`AnalyticsDataScopeService`):**
  - Multi-tenant boundary enforcement: non-superadmin users are strictly blocked (`AuthorizationException`) from accessing data belonging to any organization other than their own.
  - Dynamic SQL WHERE clause generation (`buildOrganizationScopeFilter`) enforcing `organization_id = :scoped_org_id` for tenant queries and `1 = 0` for unscoped users.
  - Field-level redaction (`redactSensitiveMetrics`) masking financial figures (`[REDACTED]`) from payload outputs when users lack `analytics.view_financial`.
