## 1. Subphase Scope & Objective
Establish the foundational Metric Registry and Semantic Layer enforcing the core architectural boundaries of analytics:
- **Architectural Rules (`02-architecture/DOMAIN_BOUNDARIES.md` & `02-architecture/SYSTEM_ARCHITECTURE.md`):**
  - "Analytics cannot be consulted as authoritative billing/payment state."
  - "Business state source-of-truth lives in domain persistence; cache/analytics are derived."
  - "Trusted dashboards without making analytics source-of-truth."
  - "Analytics Metric Registry/Semantic Layer; revenue/cash/invoice ayrımı" (`00-overview/DECISION_REGISTER.md`).
- **Semantic Classification & Separation:**
  - **Invoice Domain (`INVOICE`):** Billed accounting obligations (`invoiced_gross`, `invoiced_net`, `invoiced_tax`, `invoices_issued_count`, `outstanding_receivables`).
  - **Cash Domain (`CASH`):** Actual bank and payment gateway liquidity settlements (`cash_inflow`, `cash_refunded`, `net_cash_flow`).
  - **Subscription Domain (`SUBSCRIPTION` / `REVENUE`):** Normalized MRR/ARR run-rates of active contracts (`mrr`, `arr`, `new_mrr`, `expansion_mrr`, `contraction_mrr`, `churned_mrr`, `active_subscriptions_count`).
  - **Operations / Support Domain (`SUPPORT` / `OPERATIONS`):** Service desk and operational health (`tickets_opened_count`, `first_response_time_avg`, `sla_compliance_rate`).
- **Metric Registry (`MetricRegistry`):**
  - Canonical catalog registering all metric keys, metadata, human titles, descriptions, data types, time grains, formulas, and allowed dimension slices.
  - Dimension compatibility and query validation (`validateQuery`).
- **Semantic Layer Service (`SemanticLayerService`):**
  - Canonical value formatting across currency, percentage, count, ratio, and duration types.
  - Derived metric computation engine (`computeDerivedMetric` for `net_cash_flow`, `arr`).
  - Machine-readable catalog introspection (`getSemanticCatalog`) for UI dashboard builders and BI consumers.
