## Güven sınırı ve değişiklik

Eski public/default anahtarın MAC’i bağımsız özgünlük kanıtı sayılmaz. PrivacyLegacyMaintenance yalnız explicit maintenance onayı, ayrı güvenilir inceleme sonucundan alınmış manifest SHA256 değeri ve boş olmayan provenance ile çalışır. Kendi transaction’ını ister; raw/managed caller transaction’ı reddeder. Kaynak manifest SHA256’nin doğru olması tek başına özgünlük kanıtı değildir: beklenen digest ve provenance bağımsız inceleme/onay kanalından gelmelidir. Araç mevcut veritabanından manifest çıkarıp kendiliğinden onaylamaz. CLI HTTP kullanımını reddeder ve kayıt/anahtar içeriği çıktılamaz.

Manifest’in bütün legacy entry’leri hazırlanır; DB entry’leri mevcut satırın tüm projection’u ile canonical olarak birebir eşleşmek zorundadır. SELECT FOR UPDATE destekli DB’de satır kilidi tutulur. File entry’leri mevcut orijinal dosya içeriğiyle aynı olmalıdır; file SH lock onay kanıtı yazılana kadar tutulur. Eksik alan, duplicate/source mismatch, yanlış digest/onay, unsupported yeni v2 kayıt ve email mapping hatası kanıt yazımından önce reddedilir. Runtime’da legacy fallback veya otomatik yeniden imzalama yoktur.

PrivacyLegacyAttestation, eski semantik alanların tümü ve orijinal signature’ın digest’ini güçlü yeni purpose key ile imzalar. Proof purpose/subject/source digest/provenance/time/email-hash-scheme/key-ID alanları da korunur. Tombstone subject user ID; redaction subject audit record ID. Yeni v2 kayıtlar proof’a ihtiyaç duymaz. Eski boş signature’lı consent marker, bağımsız inceleme varsa ancak explicit id-only şemasıyla onaylanabilir. legacy-public-v1 email şeması mevcut eski public salt eşleştirmesini yalnız güçlü onay doğrulandıktan sonra kullanır. Bilinmeyen custom eski email salt’ı tahmin edilmez; id-only seçimi email üzerinden farklı kimliği bulma garantisi vermez.

PrivacyLegacyEvidenceStore signed proof’ları uygulama/DB backup dışında `PRIVACY_LEGACY_EVIDENCE_FILE` konumunda tutar. Proof dosyasında orijinal kayıt içeriği veya anahtar bulunmaz; semantic digest ve imzalı provenance vardır. Orijinal DB satırı ve legacy tombstone dosyası maintenance sırasında byte olarak değiştirilmez. Proof’lar bakım sırasında append edilir; existing proof’ın body/source/provenance/key kararının değiştirilmesi reddedilir. Aynı kaynak ikinci kez onaylanınca 0 döner ve dosya değişmez. Read/merge/write tek lock ile yapılır, flush/fsync denetlenir. Yeni incoming çelişki dosya açılmadan reddedilir; mevcut bozuk/eksik configured proof file sessizce boş kabul edilmez.

Tombstone/audit servisleri ve FileTombstoneStore legacy kayda proof’ı bellekte bağlar. Record MAC/proof semantic body ve subject doğrulanmadan authoritative getAll/sync/restore kullanımı yapılamaz. İmzalı manifest export proof’ı da taşır; aynı strong key ile başka out-of-band store’a import mümkündür. Restore edilmiş DB satırı ve authenticated file aynı semantik alanları/orijinal signature’ı taşıyorsa dosyadaki onay kanıtı bellekte DB kaydına bağlanır, DB ID’si korunur. Bunu DB alanına yazmak veya mevcut DB satırını yeniden imzalamak gerekmez. Eski raw getters/consent deny marker varlık kontrolü bağımsız silme kanıtı sayılmaz.

## Bakım kullanımı

Writers durdurulur; mevcut eski DB/file envanteri bağımsız olarak incelenir. İncelemeyi yapan güvenilir süreç manifest’i ve onun beklenen SHA256’sini sağlar. Aynı mevcut DB’den hesaplanan hash’i tek başına bağımsız onay kabul etmeyin. Henüz proof dosyası olmayan bir absolute destination ve mevcut özel parent directory kullanılabilir; dosya uygulama dizininde olamaz. Privacy signing keys önceki paketin protected files’ıdır. Proof dosyası nonsecret ve HMAC ile authenticated; bu paket ona yeni OS ACL yönetimi eklemez. Backup/restore için orijinal out-of-band tombstone kayıtlarıyla birlikte proof envanteri ve privacy keys ayrıca korunur; proof digest’i tek başına kaybolmuş orijinal kaydı yeniden oluşturamaz.

```text
PRIVACY_LEGACY_EVIDENCE_FILE=<absolute-outside-application/legacy-evidence.json>
php tools/privacy-legacy-maintenance.php --maintenance --confirmed-independent-evidence --manifest=<reviewed-manifest.json> --expected-sha256=<independently-approved-64-hex> --provenance=<review-reference> [--legacy-tombstone-file=<original-tombstones.json>]
```

Manifest biçimi `{"version":1,"records":[{"source":"database|file","purpose":"tombstone|redaction","data":{...full original row...},"email_hash_scheme":"legacy-public-v1|id-only|none"}]}`. File source yalnız tombstone içindir. Tombstone için legacy-public-v1 veya id-only; redaction için none kullanılır. DB `data` bütün mevcut SELECT * projection’unu exact tip/değerleriyle içermelidir. Bir id için farklı DB/file semantic geçmişi varsa onay envanteri bunlardan birini sessizce tercih etmez. Actual production veri veya anahtar üzerinde bu CLI çalıştırılmadı; GitHub push deployment değildir.
