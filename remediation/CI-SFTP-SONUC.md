# GitHub SFTP aktarım testi ortam hatası

Paylaşılan hata [38870947131 numaralı GitHub koşusunda](https://github.com/Boydaksu/colezahost/actions/runs/38870947131) doğrulandı: PHP 8.4.26 / PHPUnit 13.4.3, Ubuntu 24.04, 35 vaka, 12 error + 2 failure. Ana plan/locked manifest işi başarılıydı; hata SFTP yapılandırmasındaydı. Eski son dört transport koşusunun başarısızlığı yerel Windows başarısından ayrı ele alındı.

SFTP protokolünün ve PHP CURLOPT_SSH_HOST_PUBLIC_KEY_SHA256 sabitinin varlığı, runtime SSH backend'in bu seçeneği desteklediğini kanıtlamıyordu. Linux/WSL libcurl 8.5.0 + libssh 0.10.6 üzerinde aynı setopt ağ isteği olmadan CURLE_UNKNOWN_OPTION=48 verdi. Bu sürümün [resmi curl kaynak kodu](https://github.com/curl/curl/blob/curl-8_5_0/lib/setopt.c) SHA256 seçeneğini USE_LIBSSH2 koşuluna alır. [Debian bookworm libcurl4](https://packages.debian.org/bookworm/libcurl4) libssh2 kullanır; [resmi PHP bookworm CLI image'i](https://github.com/docker-library/php/blob/master/8.4/bookworm/cli/Dockerfile) bu libcurl ile derlenir. Güncel curl sürümlerindeki farklı backend desteği genellenmedi; kabul gerçek native setopt sonucuna bağlıdır.

İlk düzeltmenin [38872583973 numaralı koşusunda](https://github.com/Boydaksu/colezahost/actions/runs/38872583973) Windows ve unsupported Ubuntu işleri geçti, Linux SFTP de geçti; bu kez libcurl 7.88.1 üzerindeki S3 imza sorunu açığa çıktı (52 vaka, S3 kaynaklı 12 error + 2 failure). [Bu curl sürümünün make_headers uygulaması](https://github.com/curl/curl/blob/curl-7_88_1/lib/http_aws_sigv4.c) CURLOPT_HTTPHEADER listesindeki boş Expect: kontrol başlığını da signed headers'a ekliyordu; libcurl bu başlığı HTTP isteğinde göndermez. Bağımsız fixture doğrulaması dolayısıyla haklı olarak 403 veriyordu. S3 transport'tan bu gereksiz kontrol başlığı kaldırıldı; 100-continue müzakeresi libcurl'e bırakıldı. SigV4/payload hash/kimlik/TLS denetimi veya fixture'ın canonical imza kontrolü gevşetilmedi. Aynı bozuk istek koşulu uygun olmayan bir test beklentisi sayılıp geçilmedi.

SftpCurlBackupTransport artık geçerli config sonrası native SHA256 pin desteğini bir bağlantısız handle üzerinde ölçer. Uygun değilse constructor aşamasında açıklayıcı hata verir; güvenilmeyen SSH bağlantısı veya MD5/TOFU/unpinned fallback yoktur. Başka bir handle yapılandırma hatası download dosyasını açmadan gerçekleşir. Desteklenen ortamda mevcut gerçek protokol davranışı korunur.

GitHub workflow üç zorunlu iş çalıştırır: resmi PHP 8.4 Debian bookworm container içinde gerçek HTTPS/SigV4 + pinned SFTP; Windows üzerinde aynı gerçek testler; standart Ubuntu 24.04 PHP ortamında unsupported runtime'ın transferden önce reddedildiğini kanıtlayan negatif probe. Desteklenen iki işte 35 transport + 17 config vakası atlanmadan çalışır. Şifre/private-key auth, yanlış host pin, bozulan aktarım/readback, collision/concurrent writers ve retention testleri korunur. Linux Composer PHAR SHA256 kontrolüyle indirilir; protocol Python bağımlılıkları yalnız ayrı venv içindedir. Negatif probe simulated transport değildir: gerçek native cURL desteğini ve constructor admission sonucunu karşılaştırır.

Yerel son doğrulama: **52 protokol/config testi / 144 assertion** ve **2065 tam ana test / 12977 assertion**, exit 0, failure/error/skip yok. Windows runtime probe libcurl 8.21.0 + libssh2 1.11.1 ve SHA256 kabulünü kaydeder. Linux/WSL before probe unsupported durumu kaydeder. GitHub üzerindeki yeni üç işin canlı sonucu bu commit'in Actions kontrollerinden ayrıca doğrulanır; yerel Windows testi Linux başarılıymış gibi sunulmaz.

26 canonical migration byte olarak değişmedi. S3/SFTP transport dışındaki DB/migration/restore/privacy kaynakları bu düzeltmede değişmedi; MariaDB suite bu ara düzeltmede tekrar çalıştırılmadı. D05.4'ün ilk iki kontrolü kapalı kalır; gerçek migration ve staged yayınlama/rollback iki açık kontroldür. Bu CI düzeltmesi migration kontrolünü tamamlamış sayılmaz ve production_ready değildir. Üretim deployment/restore/harici hesap aktarımı yapılmadı.

Kanıt: CI-SFTP-baseline/origin/before-linux/windows-runtime/main/protocols dosyaları. Runtime probe desteklenen hostta `php tests/Support/sftp-runtime-probe.php supported`, Ubuntu negatif kabul işinde `unsupported` argümanı ile çalışır. Bu argüman yalnız test beklentisidir; uygulama güvenlik kontrolünü değiştirmez.
